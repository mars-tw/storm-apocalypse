## 手機／平板總稽核處置

- 觸控裝置標題 CTA 顯示「虛擬搖桿移動 · 揮砍鈕攻擊」；遊戲內攻擊、移動與 B 建造提示分別改為「揮砍鈕」「搖桿」「整備」。
- 手機手冊預設收合為「手冊 章號 · 進度」頂部小條；手冊／整備至少 48px 高，商店、關閉、波次與攻擊維持至少 44px。
- 390px HUD 分成品牌／波次與三格資源兩列；開波鈕移到左右手控制上方；左右手控制明確指定 grid 欄位，不互相覆蓋。
- 1024px 觸控使用單列 HUD、320px 收合面板與左右手控制的中間版面，不直接套 390px 手機排列。
- 四向 safe area 已套用到 HUD、面板與底部控制。
- 行動 UA、1024px 以下觸控或弱硬體自動選低畫質；低檔使用較低內部解析度、512 陰影、低粒子、關閉 bloom，最低效能目標為 30 FPS。

## 驗證

- `npm run build`：TypeScript 零錯，Vite production build 通過（只有既有大型 Babylon bundle 警告，非錯誤）。
- 390×844 觸控 Chrome：自動低畫質、CTA／情境提示為觸控文案、無水平溢位；Playwright 點擊揮砍後 `data-last-attack` 更新，實際拖曳搖桿使玩家 x 由 -0.50 移至 0.33。手冊／整備為 48px 高，揮砍 72px、開波 46px、商店項目 52px、面板關閉鈕 44px；整備面板可由 `scrollTop 0 → 180.8` 捲動。console error 0。
- 1024×768 觸控 Chrome：自動低畫質，使用單列資源 HUD、左右搖桿／攻擊與 320px 收合面板；手冊可由 x=-324 滑入至 x=14，無水平溢位。console error 0。
- 1536×864 Chrome（fine pointer）：自動高畫質，CTA 回到「WASD 移動 · 空白鍵攻擊」，桌機雙側面板常駐、虛擬搖桿隱藏，無水平溢位。console error 0。
- 低畫質策略以 30 FPS 為最低目標；受控 Chrome agent tab 會被瀏覽器背景節流，因此其即時 FPS 數字不作實機 GPU 基準，但低檔選擇、解析度／陰影／粒子／後製降級均已在行動裝置模式生效。
